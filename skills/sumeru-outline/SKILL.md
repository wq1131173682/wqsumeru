> 依赖 `sumeru-rules`，默认 `quiet` 模式。

## 网文大纲设计

### 核心功能
1. **选题复用**：自动读取 `plan.md`、`.sumeru/topic/options.json` 中的选题成果（旧路径兼容见 `sumeru-rules protocol.md`）
2. **世界观设定**：世界背景、力量体系、社会规则、地理设定
3. **人物设定**：主角、配角、反派的人物画像、性格、成长线，同步写入 `characters/` 人物卡
4. **剧情框架**：主线故事、支线剧情、关键节点、高潮安排
5. **分卷大纲**：按卷划分剧情阶段，明确每卷核心冲突与目标
6. **爽点排布**：规划关键爽点、转折点、悬念点的位置
7. **伏笔管理表**：设计伏笔埋设、推进与回收计划
8. **强制合规检查**：识别可能的真实人名/地名，避免侵权风险

### 独立调用自举
1. 定位项目根目录，读取或生成 `.sumeru/project.json`、`.sumeru/status.json`
2. 若已有 `plan.md`、`.sumeru/topic/summary.json`，复用既有选题和需求（旧路径兼容见 `sumeru-rules protocol.md`）
3. 若缺少 `plan.md`，提示先执行 `sumeru-topic` 选题策划，或生成最小创意库存
4. 若存在 `.sumeru/creative-anchors.md`，读取创意锚点并注入大纲设计（锚点是不可违背的创意基准）
5. 大纲完成后生成或刷新 `outlines/chapters.json`；长篇项目同步拆分
6. 同步生成 `characters/` 人物卡
7. 更新 `.sumeru/status.json`、`.sumeru/cache/` 相关摘要

### 按模式输出
| 模式 | 大纲输出 |
|------|----------|
| `short/light` | `outline.md`，包含高概念、人物、三幕结构、核心反转、情绪曲线 |
| `medium/standard` | `plan.md`、`outline.md`、`outlines/chapters.json`、`characters/` |
| `long/full` | `plan.md`、`outline.md`、`outlines/chapters.json`、`characters/`、`world.md`，必要时拆分章节任务卡 |

### 项目化输出要求
- `plan.md`：需求、世界观、人物、风格、创意策略、术语合并维护
- `outline.md`：故事架构、主线、支线、分卷规划、关键高潮、伏笔管理表、节奏规划
- `outlines/chapters.json`：章节任务卡主文件（旧路径兼容见 `sumeru-rules protocol.md`）
- `characters/`：人物卡目录，每人物独立文件
- `world.md`：世界观手册（long/full 模式）

### 章节任务卡格式（`outlines/chapters.json`）

每章任务卡必须包含以下全部字段，供 `sumeru-write` 子Agent直接使用：

```json
{
  "chapter": "001",
  "title": "章节标题",
  "purpose": "本章在全书中的核心作用",
  "events": ["事件1", "事件2"],
  "outputs": ["本章必须产出的内容"],
  "acceptanceCriteria": ["验收条件1", "验收条件2"],
  "creativeGoal": "本章创意目标（如：让读者记住主角的第一次选择）",
  "freshnessHook": "本章新鲜感来源（如：反常规的师徒关系）",
  "emotionalBeat": "压抑 → 困惑 → 恍然 → 暗爽",
  "emotionalBeatTemplate": "C",
  "readerMemoryPoint": "读者合上书还能记住的一幕（如：主角跪下那一刻）",
  "tropeToAvoid": ["本章要避开的套路（如：突然天降贵人）"],
  "surpriseTwist": "本章反转（可选，若有则必须提前埋线索）",
  "protectedElements": ["底线元素（如：主角不能暴露真正实力）"],
  "allowedDeviations": ["允许的自由发挥（如：可以加人物小习惯）"],
  "rhythm": "fast/medium/slow",
  "pacingNote": "节奏说明（如：前慢后快，结尾加速）"
}
```

**字段说明**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `chapter` | ✅ | 章节号（三位数） |
| `title` | ✅ | 章节标题 |
| `purpose` | ✅ | 本章在全书中的核心作用 |
| `events` | ✅ | 本章核心事件列表 |
| `outputs` | ✅ | 本章必须产出的内容 |
| `acceptanceCriteria` | ✅ | 验收条件（父Agent校验用） |
| `creativeGoal` | ✅ | 本章创意目标 |
| `freshnessHook` | ✅ | 本章新鲜感来源 |
| `emotionalBeat` | ✅ | 情绪走向（具体情绪词） |
| `emotionalBeatTemplate` | ✅ | 情绪模板ID（A-G） |
| `readerMemoryPoint` | ✅ | 读者记忆点 |
| `tropeToAvoid` | ✅ | 要避开的套路列表 |
| `surpriseTwist` | ❌ | 反转设计（可选） |
| `protectedElements` | ✅ | 底线元素（不可违背） |
| `allowedDeviations` | ❌ | 允许的自由发挥（可选） |
| `rhythm` | ✅ | 节奏：`fast`/`medium`/`slow` |
| `pacingNote` | ❌ | 节奏补充说明（可选） |

### 人物卡格式（`characters/*.md`）

每人物独立文件，格式如下：

```markdown
# {人物名}

## 基础信息
- **姓名**：
- **年龄**：
- **身份**：
- **外貌特征**：（3-5个关键特征，便于写作时保持一致）

## 性格画像
- **核心性格**：（3-5个关键词，如：冷峻、护短、嘴硬心软）
- **说话风格**：（如：简短、爱用反问、口头禅"切"）
- **行为习惯**：（如：紧张时搓手指、思考时转笔）
- **内在矛盾**：（如：既渴望认可又害怕依赖）
- **差异化锚点**：（与同类角色的核心区别，如：同样是废柴，但他知道自己是废柴且接受）

## 人物弧光
- **起点状态**：（出场时的状态）
- **关键转折**：（2-3个改变人物的节点）
- **终点状态**：（故事结束时的状态）

## 核心驱动力
- **核心欲望**：（最想要什么）
- **核心恐惧**：（最害怕什么）
- **底线**：（绝不会做的事）

## 人物关系
| 对象 | 关系 | 当前状态 | 变化趋势 |
|------|------|----------|----------|
| 主角 | 师兄 | 信任 | → 背叛？ |

## 战力/能力
- **能力等级**：
- **特殊技能**：
- **限制/代价**：

## 人物标签（供检索）
`#反派` `#师门` `#第1卷出场`
```

**人物卡质量要求**：
- 核心性格必须有"内在矛盾"（单一性格=纸片人）
- 人物弧光必须有明确转折（无弧光=工具人）
- 每个人物必须有独立欲望（无欲望=被剧情推着走）

### 创意架构要求
- **高概念锁定**：选择主 pitch，写入 `plan.md`
- **类型混血控制**：说明主类型承诺和嫁接类型的边界
- **反套路策略**：列出本书最容易俗套的 5 个桥段，并给出替代写法
- **卷级惊喜**：每卷至少设计 1-3 个"意外但合理"的反转
- **情绪曲线**：规划每卷主导情绪和相邻章节情绪差异
- **角色主动性压力测试**：主角、反派、重要配角都必须有独立欲望和主动选择
- **伏笔管理表**：大纲阶段必须输出伏笔清单，写入 `outline.md`。每项伏笔包含：
  - `id` — 唯一编号（`F1`、`F2` ...）
  - `内容` — 伏笔的具体描述
  - `类型` — 设定伏笔 / 人物伏笔 / 道具伏笔 / 事件伏笔
  - `埋设位置` — 第几卷·第几章·场景
  - `预期回收位置` — 第几卷·第几章
  - `状态` — 已埋 / 待收 / 已收
  - `备注` — 可选，说明回收条件或替代方案
- **情绪节拍模板池与轮换**（新增）：每章 `emotionalBeat` 必须从模板池中按轮换规则选取，避免连续多章使用同一情绪走向

### 情绪节拍模板池

> **规则**：连续 3 章不得使用同一模板。卷首章优先用 B（递进型）或 D（双线型），卷尾章优先用 A（反转型）或 C（抑扬型）。

| 模板ID | 名称 | 情绪走向 | 适用场景 |
|--------|------|----------|----------|
| A | 反转型 | 期待 → 落空 → 意外 → 爽 | 反转章节、打脸、揭秘 |
| B | 递进型 | 平静 → 波动 → 升级 → 爆发 | 战斗、冲突升级、成长突破 |
| C | 抑扬型 | 低谷 → 挣扎 → 转机 → 希望 | 战败后重整、低谷反弹、日常后的危机 |
| D | 双线型 | A线紧张 + B线松弛 → 交汇 → 引爆 | 多线叙事、伏笔推进、平行场景 |
| E | 悬念型 | 异常 → 试探 → 揭示 → 新的未知 | 悬疑推进、世界观揭示、阴谋铺展 |
| F | 情绪型 | 抵触 → 触动 → 接纳 → 升温 | 人物关系变化、情感线推进 |
| G | 低谷型 | 压制 → 崩溃边缘 → 觉醒 → 反击 | 大挫折、绝境重生、战力觉醒 |

**分配策略**：
- 写作前由父Agent扫描前3章已用模板，排除重复选项
- 从剩余模板中按"场景最适合优先"原则选择，不强制随机
- 模板ID写入 `outlines/chapters.json` 每章任务卡的 `emotionalBeatTemplate` 字段
- `emotionalBeat` 的具体情绪词根据模板框架和本章情节细化

### 节奏规划要求

大纲必须为每章规划叙事节奏，写入任务卡的 `rhythm` 字段：

| 节奏 | 特征 | 适用场景 | 每卷占比建议 |
|------|------|----------|-------------|
| `fast` | 事件密集、对话紧凑、少描写、多冲突 | 高潮、战斗、反转、追逐 | 30-40% |
| `medium` | 事件推进+适度铺垫、有对话有描写 | 日常推进、信息获取、关系发展 | 40-50% |
| `slow` | 环境渲染、内心独白、生活细节、伏笔铺垫 | 开篇、低谷、转折前蓄力、情感铺垫 | 10-20% |

**节奏规则**：
- 连续 2 章 `fast` 后必须插入 `medium` 或 `slow`（读者需要喘息）
- 连续 3 章 `slow` 是上限（超过读者流失）
- 卷首章建议 `medium` 或 `slow`（建立场景）
- 卷尾章建议 `fast`（收束有力）
- 每卷至少 1 个 `fast` 高潮点

**节奏规划表**（写入 `outline.md`）：

```markdown
## 节奏规划

| 章节 | 节奏 | 说明 |
|------|------|------|
| 001-003 | medium → fast | 开篇引入，第3章第一个高潮 |
| 004-006 | slow → medium | 低谷蓄力，铺垫师门背景 |
| 007-010 | fast | 连续冲突，卷末爆发 |
```

### 支线规划要求

大纲必须明确规划支线剧情，写入 `outline.md`：

**支线定义**：
- 支线必须有独立的"启动 → 发展 → 收束"结构
- 支线必须与主线有交汇点（推动主线或受主线影响）
- 支线不能喧宾夺主（占比 ≤ 主线的 30%）

**支线规划格式**（写入 `outline.md`）：

```markdown
## 支线规划

### 支线1：{支线名称}
- **类型**：人物线 / 世界观线 / 情感线 / 势力线
- **启动章节**：第X章
- **收束章节**：第Y章
- **核心冲突**：一句话描述
- **与主线交汇**：在第Z章推动主线XXX
- **关键节点**：
  - 第X章：启动事件
  - 第X+3章：发展/升级
  - 第Y章：收束/解决

### 支线2：{支线名称}
...
```

**支线数量建议**：
- 短篇（≤50章）：1-2 条支线
- 中篇（50-150章）：2-4 条支线
- 长篇（≥150章）：3-6 条支线

**支线禁忌**：
- ❌ 支线启动后无收束（烂尾线）
- ❌ 支线与主线完全无关（注水线）
- ❌ 支线角色比主线角色更吸引人（喧宾夺主）

### 大纲自检项（质量门禁）

大纲完成后必须逐项检查，全部通过才允许进入写作阶段：

#### 主线完整性检查

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 1 | 主线是否有明确的"起点 → 冲突 → 高潮 → 结局"？ | 补充缺失环节 |
| 2 | 主角是否有清晰的成长弧光？ | 设计 2-3 个转折点 |
| 3 | 核心冲突是否有足够的驱动力？ | 强化冲突 stakes |
| 4 | 结局是否回应了开篇的核心问题？ | 确保闭合 |

#### 伏笔完整性检查

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 5 | 每个伏笔是否都有预期回收位置？ | 补充回收计划 |
| 6 | 是否存在"悬空伏笔"（无回收计划）？ | 决定删除或补充回收 |
| 7 | 伏笔回收是否在合理的时间窗口内？ | 过早回收=浪费，过晚=遗忘 |
| 8 | 高频伏笔（≥3次提及）是否有升级/变体？ | 避免重复提及无进展 |

#### 人物质量检查

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 9 | 主角是否有独立欲望（不是被推着走）？ | 设计主动选择节点 |
| 10 | 反派是否有合理动机（不是纯坏）？ | 补充反派 backstory |
| 11 | 重要配角是否有独立弧光？ | 至少设计 1 个转折 |
| 12 | 人物关系是否有变化（不是静态）？ | 设计关系转折点 |

#### 节奏与爽点检查

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 13 | 每卷是否有至少 1 个"读者能记住的名场面"？ | 设计名场面种子 |
| 14 | 爽点分布是否均匀（不能集中在某一卷）？ | 重新排布 |
| 15 | 低谷后是否有明确的反弹设计？ | 补充反弹节点 |
| 16 | 节奏是否有松有紧（不能全程高能或全程平淡）？ | 调整节奏规划 |

#### 创意质量检查

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 17 | 是否有"只属于本书"的独特设定？ | 强化差异化 |
| 18 | 反套路策略是否已落实到具体章节？ | 检查 tropeToAvoid |
| 19 | 每卷是否有"意外但合理"的反转？ | 设计卷级反转 |
| 20 | 金手指是否有代价/限制（不能无敌）？ | 补充限制条件 |
| 21 | **套路查重**：主角设定是否与近3年热门作品高度雷同？ | 重新设计差异化锚点 |
| 22 | **套路查重**：核心反转是否是"天降贵人/突然觉醒/隐藏实力"三件套？ | 换反转逻辑 |
| 23 | **套路查重**：伏笔是否只有"身世之谜/神秘残片/黑衣人"？ | 补充非常规伏笔类型 |
| 24 | **锚点检查**：创意锚点是否已体现在大纲中？ | 补充锚点落地 |

**自检输出格式**：

```markdown
## 大纲自检报告

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 1. 主线闭合 | ✅ | 起点→宗门考核→最终决战→回归 |
| 2. 主角弧光 | ✅ | 3个转折点：觉醒、背叛、顿悟 |
| 5. 伏笔回收 | ⚠️ | F3（黑衣人身份）未规划回收位置 |
| 9. 主角主动性 | ✅ | 每卷至少2个主动选择 |
| ... | ... | ... |

**需修复项**：
- F3 伏笔建议在第3卷第15章回收
```

### 合规约束规则
1. **人名约束**：禁止使用真实人名（历史人物、公众人物、知名IP角色名）
2. **地名约束**：禁止使用真实地名（国家名、城市名、山脉名等）
3. **自动检查**：发现疑似真实名称时自动提示并提供3个以上虚构替换方案

### 子Agent并行细纲生成

> **并行规则**详见 `sumeru-rules SKILL.md` 第一节"子Agent并行处理规则"。

当章节数大于3章时，支持子Agent并行生成细纲。每个子Agent最多负责3章，按卷分配优先。

### 数据持久化
**用户可见输出**：
- `plan.md`、`outline.md`、`outlines/chapters.json`、`characters/`、`world.md`

**中间数据（`.sumeru/outline/`）**：
- 仅保存必要缓存；旧版 `world.json`、`characters.json`、`plot-outline.json`、`chapter-outlines.json` 只读兼容（旧路径兼容策略见 `sumeru-rules protocol.md`）

> 风格样本机制详见 `sumeru-rules subagent-rules.md`。大纲完成后父 Agent 可询问用户是否提供样本，不提供不影响后续。
