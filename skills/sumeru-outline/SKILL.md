## 网文选题策划

### 核心功能
1. **市场热点分析**：基于类型经验和模型知识推断网文题材趋势，非实时榜单结论
2. **多维度选题生成**：生成3-5个具有市场潜力的选题方向
3. **核心创意设计**：为每个选题设计金手指、核心设定、爽点模式、情绪价值曲线
4. **选题可行性评估**：从市场竞争、受众规模、创作难度、变现潜力等维度评估
5. **创作方向建议**：提供开篇切入点、故事节奏规划、人物设定框架、差异化竞争策略
6. **风险提示**：识别选题可能面临的政策风险、市场饱和风险、题材生命周期等问题

### 创意引擎输出要求（每次选题必须包含）
1. **高概念 Pitch**：至少 3 个一句话 pitch，包含核心反差、爽点来源、代价/限制、传播句
2. **类型混血**：至少 3 种类型嫁接方案
3. **金手指变异**：对常见金手指做至少 5 个变体
4. **反套路替代**：列出最容易落入的套路，并给出替代写法
5. **读者记忆点**：每个候选选题至少给 2 个可传播名场面或安利句
6. **创意评分表**：按新鲜度、爽感、合理性、可持续性、传播性、类型契合度评分

### 分析边界
- 市场判断基于模型知识和类型经验，不等同于实时榜单数据
- 没有用户提供实时数据时，必须标注"非实时数据推断，需结合平台最新榜单验证"
- 不输出过度精确的热度排名、变现概率或平台收益判断
- 选题应强调原创差异化，不直接套用知名作品

## 网文大纲设计

### 核心功能
1. **选题复用**：自动读取 `plan.md`、`.sumeru/topic/options.json` 或旧版 `docs/requirements.md` 中的选题成果
2. 世界观设定：世界背景、力量体系、社会规则、地理设定
3. 人物设定：主角、配角、反派的人物画像、性格、成长线
4. 剧情框架：主线故事、支线剧情、关键节点、高潮安排
5. 分卷大纲：按卷划分剧情阶段，明确每卷核心冲突与目标
6. 爽点排布：规划关键爽点、转折点、悬念点的位置
7. **强制合规检查**：识别可能的真实人名/地名，避免侵权风险

### 独立调用自举
1. 定位项目根目录，读取或生成 `.sumeru/project.json`、`.sumeru/status.json`
2. 若已有 `plan.md`、`.sumeru/topic/summary.json` 或旧版 `docs/requirements.md`，复用既有选题和需求
3. 若缺少 `plan.md`，先执行选题策划（生成最小创意策略和创意库存），再进入大纲
4. 选题完成后更新 `.sumeru/project.json`、`plan.md`、`.sumeru/topic/options.json`、`.sumeru/topic/summary.json`
5. 大纲完成后生成或刷新 `outlines/chapters.json`；长篇项目同步拆分
6. 更新 `.sumeru/status.json`、`.sumeru/cache/` 相关摘要

### 按模式输出（选题 + 大纲）
| 模式 | 选题输出 | 大纲输出 |
|------|----------|----------|
| `short/light` | 1-3个高概念创意，选一个方向 | `outline.md`，包含高概念、人物、三幕结构、核心反转、情绪曲线 |
| `medium/standard` | 3个选题方案，更新 `plan.md` | `plan.md`、`outline.md`、`outlines/chapters.json` |
| `long/full` | 3-5个选题方案，更新 `plan.md` 和 `.sumeru/topic/options.json` | `plan.md`、`outline.md`、`outlines/chapters.json`，必要时拆分章节任务卡 |

### 项目化输出要求
- `plan.md`：需求、世界观、人物、风格、创意策略、术语合并维护
- `outline.md`：故事架构、主线、分卷规划、关键高潮、伏笔管理表
- `outlines/chapters.json`：章节任务卡主文件（每章必须包含 `purpose`、`events`、`outputs`、`acceptanceCriteria`）

### 创意架构要求
- **高概念锁定**：选择主 pitch，写入 `plan.md`
- **类型混血控制**：说明主类型承诺和嫁接类型的边界
- **反套路策略**：列出本书最容易俗套的 5 个桥段，并给出替代写法
- **卷级惊喜**：每卷至少设计 1-3 个"意外但合理"的反转
- **情绪曲线**：规划每卷主导情绪和相邻章节情绪差异
- **角色主动性压力测试**：主角、反派、重要配角都必须有独立欲望和主动选择
- **伏笔管理表**：大纲阶段必须输出伏笔清单，写入 `outline.md`。每项伏笔包含：
  - `id` — 唯一编号（`F1`、`F2` ...）
  - `内容` — 伏笔的具体描述
  - `类型` — 设定伏笔 / 人物伏笔 / 道具伏笔 / 事件伏笔
  - `埋设位置` — 第几卷·第几章·场景
  - `预期回收位置` — 第几卷·第几章
  - `状态` — 已埋 / 待收 / 已收
  - `备注` — 可选，说明回收条件或替代方案

### 合规约束规则
1. **人名约束**：禁止使用真实人名（历史人物、公众人物、知名IP角色名）
2. **地名约束**：禁止使用真实地名（国家名、城市名、山脉名等）
3. **自动检查**：发现疑似真实名称时自动提示并提供3个以上虚构替换方案

### 子Agent并行细纲生成
当章节数大于3章时，支持子Agent并行生成细纲。每个子Agent最多负责3章，按卷分配优先。

### 数据持久化
**用户可见输出**：
- `选题策划报告.md`（可选）、`plan.md`、`outline.md`、`outlines/chapters.json`

**中间数据（`.sumeru/topic/`）**：
- `report.md`：选题完整报告备份
- `options.json`：结构化选题数据（供大纲复用）
- `summary.json`：核心参数摘要

**中间数据（`.sumeru/outline/`）**：
- 仅保存必要缓存；旧版 `world.json`、`characters.json`、`plot-outline.json`、`chapter-outlines.json` 只读兼容

> 风格样本机制详见 `sumeru-rules` 子Agent规则。大纲完成后父 Agent 可询问用户是否提供样本，不提供不影响后续。
