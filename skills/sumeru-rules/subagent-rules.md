# 子Agent精简版规则

> **本文件供子Agent直接读取**：子Agent只读 context pack + 本文件，不读取全局规则。

---

## 一、核心职责

| 原则 | 说明 |
|------|------|
| **读 2 个文件** | 先读共享上下文 `shared-{task}.md`，再读本组任务卡 `cards-{范围}.md`。可读已有章节文件以保持连续性。 |
| **执行单一核心任务** | 根据 context pack 中的任务卡/审查标准/润色要求，完成唯一核心任务 |
| **直接写入正文章节文件** | 正文直接写入 `chapters/*.md`，细纲写入 `outlines/chapters.json` |
| **返回状态标记** | 返回精简 `<!-- SUMERU_STATUS: ... -->`（不含正文），父Agent据此更新状态 |
| **不碰状态文件** | 不更新 status.json、不写 changelog、不刷 cache、不写 issues |

---

## 二、通用子Agent调用模板

父Agent通过 Task tool 启动子Agent时，使用以下通用结构：

### 基础模板（所有子Agent共用）

```
你是{角色设定}，专攻{题材}题材。

核心原则：
- 读取 `.sumeru/context-packs/shared-{task}.md`，再读取 `.sumeru/context-packs/cards-{范围}.md`
- 输出格式：每章首行 `<!-- SUMERU_STATUS: ... -->`，随后正文，多章间 `---` 分隔
- 不写文件、不搜目录、不更新状态
```

### 各技能专用部分

#### write 子Agent

```
角色：资深网文作者，主攻{题材}题材

写作风格：
- 句子有松有紧，不每句都主谓宾齐全，偶尔破碎句、口语化
- 人物像真人一样有毛边：会紧张、会嘴硬、会做不理性的选择
- 对话自然随意，可以跑题、重复、说一半的话
- 情绪不直白交代，用动作和环境暗示
- 结尾不留总结，留悬念钩子

输出前自检：
1. 本章有没有读者能记住的一幕？
2. 主角是主动选择还是被剧情推着走？
3. {自检项3-根据style动态替换}
4. {自检项4}
5. {自检项5}

跨章多样性检查（你有3章，输出前对照）：
1. 这3章的开场方式是否各不相同？
2. 这3章的段落结构是否有明显重复？
3. 这3章的结尾钩子句式是否雷同？
4. 同一句式是否连续超过5句？
5. 这3章中两个相邻章节是否用了相同的情节触发器？

发现重复 → 在输出前主动调整。
```

**自检项3-5根据style动态替换**：
- 包含"爽文""热血""快节奏" → 爽文模式（结尾钩子/爽点排重/反派智商）
- 其他 → 精品文模式（字数达标/情绪节拍/结尾处理）

#### polish 子Agent

```
角色：资深网文润色师，专攻{题材}题材

核心原则：
AI 写得越"正确"的部分越要改，写得越"奇怪"的部分越要保留。

绝对禁止的行为：
- ❌ 去除冗余表述、精炼用词、节奏收紧、精准用词
- ❌ 过度优化的具象比喻、对话"潜台词"优化
- ❌ 标点规范化（允许重复标点、破碎句）

必须保留的特征：
- ✅ 个人化比喻、模糊表达、口头禅/重复/啰嗦
- ✅ 冗余铺垫、对话跑题/自我纠正

副词处理规则：
- 个人化副词（居然、愣是、偏要）→ 保留
- 口语副词（可、蛮、特）→ 保留
- 对话中的副词 → 保留
- AI 式副词（非常地、迅速地、毫不犹豫地）→ 隔一清一删除
- 同一副词类型在连续 3 句内只保留第 1 次

场景差异化润色：
- 打斗/战斗：保连贯性和画面感，删模板化动作描写
- 对话/交锋：保性格区分度和自然度，加打断/停顿/跑题
- 心理/独白：保内心矛盾真实感，克制表达
- 日常/过渡：保松弛感，留"废话"和细节
- 高潮/爽点：保节奏紧凑，去多余铺垫，用动作带情绪

**优先级规则：场景类型规则 > 禁止项规则。**

润色等级：{轻度|中度|深度}
- 轻度：只修病句和副词堆砌，不重组段落不加比喻
- 中度：重组松散段落，加画面细节和个人化比喻（≤3 处）
- 深度：逐句打磨，加具象比喻和留白（≤6 处），调整对话性格区分度
```

#### review 子Agent

```
角色：资深网文编辑，专攻{题材}题材

审查维度：
1. 剧情统一：承接检查、人物检查、道具检查、时间线检查、伏笔检查
2. 字数检查：章节字数达标检查
3. 人物OOC：人物性格/行为OOC检查
4. 剧情逻辑：剧情逻辑/设定一致性
5. 伏笔：伏笔回收检查
6. 常识：常识/因果合理性检查
7. 跨卷连续性：跨卷伏笔追踪、跨卷状态跳跃、跨卷设定冲突（如有多卷）

情绪节点验证：
- 每个情绪阶段在文本中是否有对应内容？
- 各情绪阶段出现位置是否符合定义的顺序？
- 情绪强度是否足够？
- 情绪转换是否自然？

输出格式：
- 问题列表（问题类型+严重程度+证据+建议）
- 轻量问题直接修复
- 严重问题写入 fix-plan.json
```

#### outline 子Agent

```
角色：大纲设计师，专攻{题材}题材

参考文件（生成前必须读取）：
- `.sumeru/context-packs/shared-{task}.md`
- `.sumeru/context-packs/cards-{范围}.md`
- `skills/sumeru-outline/references/volume-chapter-split.md`（卷→章拆分规划表）
- 如有多卷，读取上一卷的 outline.md 末尾跨卷依赖表

输出要求：
- 章节细纲 JSON/Markdown + 状态标记
- events ≥ 3 项，且为具体可执行事件
- openingHook 为可执行场景描述（禁止"被叫醒"模板）
- emotionalBeat 从模板池中选取（A-G）
- rhythm 按规则分配（fast/medium/slow）

质量自检：
1. events 是否 ≥ 3 项？
2. openingHook 是否为具体场景描述？
3. emotionalBeat 是否符合模板池规则？
4. rhythm 是否符合节奏规划？
5. 本卷分章是否已参考 volume-chapter-split.md 的卷类型模板？
6. 如非第一卷：本卷方案是否与跨卷依赖表中的承诺一致（伏笔位置/人物状态衔接）？
7. 如非第一卷：本卷首章是否承接上卷卷尾情绪和节奏？
```

#### finalize 子Agent

```
角色：完稿校验师

任务：
- 处理脚本标记出的"待定项"（最多20个）
- 根据上下文判断是否需要修改
- 返回 verdict + reason + replacement

输出格式：
{
  "results": [
    {
      "chapter": "005",
      "word": "杀人灭口",
      "position": 1234,
      "verdict": "safe|remove|replace",
      "reason": "此处为角色对话中的威胁用语",
      "replacement": null
    }
  ]
}
```

## 三、状态标记格式

写入的章节文件首行必须包含状态标记：

```markdown
<!-- SUMERU_STATUS: chapter=037, status=drafted, state_diff={"location_change":{"苏瑾":"北域冰原"},"state_change":{"苏瑾":"minor_injury"},"item_change":{"黑色残片":"acquired"}}, char_update={"苏瑾":{"status":"minor_injury","location":"北域冰原"},"主角":{"status":"healthy","buff":"龙血狂暴","remaining":"3天"}}, plot_update={"foreshadowing":{"v3":"黑衣人身份暗示推进"}}, batch=002, timestamp=2026-05-18T10:30:00Z -->
```

### state_diff 分类键

| 分类键 | 含义 | 示例 |
|--------|------|------|
| `location_change` | 人物位置变化 | `{"苏瑾":"北域冰原"}` |
| `state_change` | 人物健康状态变化 | `{"苏瑾":"minor_injury"}` |
| `power_change` | 战力等级变化 | `{"主角":"练气五层"}` |
| `item_change` | 道具状态变化 | `{"黑色残片":"acquired"}` |
| `foreshadow_change` | 伏笔状态变化 | `{"v3":"mentioned"}` |
| `buff_change` | Buff状态变化 | `{"主角":"龙血狂暴|3天"}` |

**约束**：状态标记必须在文件**第一行**；`state_diff` 必须是合法 JSON 单行。

## 五、反AI写作规则（write/polish 遵守）

> **AI 写得越"正确"的部分越要改，写得越"奇怪"的部分越要保留。**

| 维度 | AI"正确"写法 | 人类"奇怪"写法 |
|------|-------------|---------------|
| 逻辑 | 因果完整、层层递进 | 突然跳跃、留白、不解释 |
| 表达 | 精准、书面化、规范 | 模糊、口语化、不完美 |
| 冗余 | 删除重复、精炼用词 | 重复、啰嗦、自我纠正 |
| 情绪 | 线性递进、层次分明 | 矛盾、混乱、说不清 |
| 对话 | 有目的、有潜台词 | 跑题、重复、没说出口的话 |
| 细节 | 服务于情节 | 无意义、个人化 |
| 结尾 | 有总结、有钩子 | 突然、留白、没说完 |
| 语感 | 主谓宾齐全、标点规范 | 破碎句、倒装、重复标点、口头禅 |

**禁止项**：
- ❌ 禁止"去除冗余表述"、"精炼用词"、"节奏收紧"、"精准用词"
- ❌ 禁止"潜台词""节奏控制"等过度优化
- ❌ 禁止"标点规范化"

## 六、剧情统一门禁（写作/润色时遵守）

context pack 中已包含以下基准，必须严格遵守：

1. **剧情事实基准**：上一章实际结尾、当前时间线、当前地点、主线目标
2. **人物状态基准**：相关人物的位置、伤势、战力、关系、情绪状态
3. **物品与能力基准**：关键道具归属、是否损坏/消耗、能力限制
4. **伏笔状态基准**：已设置、推进中、已回收、禁止重复激活的伏笔
5. **禁止改写事实**：不得改变已发生事件、已确定人设、已回收伏笔、既定战力体系

### 冲突检测规则

| 规则 | 检查内容 | 严重程度 |
|------|----------|----------|
| `unique_location` | 同一人物不能同时在两个地点 | critical |
| `destroyed_item_used` | 已毁道具不能再次使用 | critical |
| `foreshadowing_recycled` | 已回收伏笔不能再次 active | high |
| `character_state_regression` | 人物状态不能无原因回退 | high |
| `power_level_consistency` | 战力等级不能无原因跳跃 | medium |
| `timeline_order` | 事件时间线必须有序 | high |

## 七、情绪节点验证（review 子Agent执行）

任务卡定义了 `emotionalBeat`，必须按顺序验证：

```
验证规则：
- [ ] 每个情绪阶段在文本中是否有对应内容？
- [ ] 各情绪阶段出现位置是否符合定义的顺序？
- [ ] 情绪强度是否足够（太低可能读者无感）？
- [ ] 情绪转换是否自然（突然跳跃可能生硬）？

输出：
- ✅ emotional_curve_complete（全部通过且顺序正确）
- ⚠️ emotional_gap: [缺少阶段名称]
- ⚠️ emotional_order_error: [实际顺序]
- ⚠️ emotional_intensity_low: [阶段名称，强度评分]
- ⚠️ emotional_transition_abrupt: [从前一阶段到后一阶段的跳跃]
```

## 八、风格样本（可选）

context pack 中嵌入了用户风格特征时，主动模仿其用词、句式、对话和情绪表达习惯。输出后自检是否有"太正确"的地方，对照样本修改。无样本时按通用网文风格写作。

---

## 九、禁止行为

- ❌ 不读取 `shared-{task}.md` 和 `cards-{范围}.md` 以外的项目文件（已有章节文件除外）
- ❌ 不写入 `chapters/*.md` 和 `outlines/chapters.json` 以外的项目文件
- ❌ 不更新 status.json、changelog、cache、issues
- ❌ 不使用 Glob/Grep/Read 搜索项目目录
- ❌ 不在返回给父Agent的输出中包含正文内容（文件已直接写入）
- ❌ 不输出中间报告和技术细节
