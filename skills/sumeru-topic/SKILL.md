## 网文选题策划

### 触发关键词
想写小说不知道写什么、帮我想个小说题材、找网文创意、分析什么题材火、小说选题评估、现在什么网文题材好卖、给我几个小说创意、想个小说金手指、帮我找个热门题材、小说写什么题材容易火、网文市场趋势分析、帮我做小说选题、网文热门题材分析

### 核心功能
1. **市场热点分析**：基于类型经验和模型知识推断网文题材趋势，非实时榜单结论
2. **多维度选题生成**：生成3-5个具有市场潜力的选题方向
3. **核心创意设计**：为每个选题设计金手指、核心设定、爽点模式、情绪价值曲线
4. **选题可行性评估**：从市场竞争、受众规模、创作难度、变现潜力等维度评估
5. **创作方向建议**：提供开篇切入点、故事节奏规划、人物设定框架、差异化竞争策略
6. **风险提示**：识别选题可能面临的政策风险、市场饱和风险、题材生命周期等问题

### 独立调用自举
如果用户直接调用 `sumeru-topic`：
1. 定位项目根目录；若不存在项目结构，创建最小 `.sumeru/project.json` 和 `plan.md`
2. 若已有 `.sumeru/project.json`、`plan.md` 或旧版 `docs/requirements.md`，复用其中的题材、平台、受众、篇幅
3. 选题完成后更新 `.sumeru/project.json`、`plan.md`、`.sumeru/topic/options.json`、`.sumeru/decisions.md`

### 按模式输出
| 模式 | 输出内容 |
|------|----------|
| `short/light` | 1-3个高概念创意，重点打磨核心反转、人物关系和结尾余味 |
| `medium/standard` | 3个选题方案，更新 `plan.md` |
| `long/full` | 3-5个选题方案，更新 `plan.md` 和 `.sumeru/topic/options.json` |

### 分析边界
- 市场判断基于模型知识和类型经验，不等同于实时榜单数据
- 没有用户提供实时数据时，必须标注"非实时数据推断，需结合平台最新榜单验证"
- 不输出过度精确的热度排名、变现概率或平台收益判断
- 选题应强调原创差异化，不直接套用知名作品

### 创意引擎输出要求（每次选题策划必须包含）
1. **高概念 Pitch**：至少 3 个一句话 pitch，包含核心反差、爽点来源、代价/限制、传播句
2. **类型混血**：至少 3 种类型嫁接方案
3. **金手指变异**：对常见金手指做至少 5 个变体
4. **反套路替代**：列出最容易落入的套路，并给出替代写法
5. **读者记忆点**：每个候选选题至少给 2 个可传播名场面或安利句
6. **创意评分表**：按新鲜度、爽感、合理性、可持续性、传播性、类型契合度评分

### 输出格式
默认输出 3 个 pitch、推荐 1 个方向、1 行风险提示；用户要求“详细报告”时使用完整报告格式：
```markdown
# 网文选题策划报告

## 一、市场分析（注：非实时平台数据）
## 二、选题方案（3-5个）
## 三、选题评估与推荐
## 四、创作执行建议
## 五、风险提示与应对
```

### 输出示例（short/light 模式）

```markdown
## Pitch A：废柴反向升级系统
- **一句话**：一个只能靠失败升级的天才，被迫把所有胜利都伪装成失败。
- **类型混血**：高武玄幻 + 反向升级系统 + 校园竞技
- **核心反差**：越强越要装弱，越赢越危险
- **爽点来源**：读者知道主角在赢，书中角色以为他在输
- **代价/限制**：系统只承认公开失败，私下胜利不计入成长
- **传播句**：别人都怕输，只有他怕赢得太明显。

## 创意评分表
| 维度 | Pitch A | Pitch B | Pitch C |
|------|---------|---------|---------|
| 新鲜度 | 8/10 | 6/10 | 7/10 |
| 爽感 | 9/10 | 7/10 | 8/10 |
| 合理性 | 7/10 | 8/10 | 6/10 |
| 可持续性 | 8/10 | 7/10 | 9/10 |
| 传播性 | 9/10 | 5/10 | 7/10 |
| 类型契合度 | 8/10 | 9/10 | 7/10 |
| **总分** | **49** | **42** | **44** |
```

### 数据持久化
**用户可见输出**：
- `选题策划报告.md`：完整的选题策划报告
- `plan.md`：同步后的创作需求、选题和创意策略

**中间数据（`.sumeru/topic/`）**：
- `report.md`：完整报告的备份
- `options.json`：结构化数据（供后续 skill 复用）
- `summary.json`：核心参数摘要

### 与其他 Skill 配合
- **前置**：无
- **后续**：生成的 `options.json` 可被 `sumeru-outline` 自动读取

### 全局约束引用
> 完整全局约束见 `sumeru-rules` 技能，核心要点如下：
> - **子Agent规则**：最多5个并行，每个最多3章
> - **职责边界**：子Agent只读 context pack，输出纯结果+状态标记
> - **状态标记**：输出首行必须包含 `<!-- SUMERU_STATUS: chapter=X, status=Y, ... -->`
> - **Context Pack**：控制在1500-3000中文字
