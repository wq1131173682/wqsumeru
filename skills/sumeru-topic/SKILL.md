## 网文选题策划

### 触发关键词
想写小说不知道写什么、帮我想个小说题材、找网文创意、分析什么题材火、小说选题评估、现在什么网文题材好卖、给我几个小说创意、想个小说金手指、帮我找个热门题材、小说写什么题材容易火、网文市场趋势分析、帮我做小说选题、网文热门题材分析

### 核心功能
1. **市场热点分析**：基于AI推理分析网文市场热点题材、流行趋势与受众偏好（注：市场分析基于AI对网文领域的知识推理，非实时数据，建议结合实际平台榜单交叉验证）
2. **多维度选题生成**：结合输入的题材类型和关键词，生成3-5个具有市场潜力的选题方向
3. **核心创意设计**：为每个选题设计金手指、核心设定、爽点模式、情绪价值曲线
4. **选题可行性评估**：从市场竞争、受众规模、创作难度、变现潜力等维度进行综合评估
5. **创作方向建议**：提供开篇切入点、故事节奏规划、人物设定框架、差异化竞争策略
6. **风险提示**：识别选题可能面临的政策风险、市场饱和风险、题材生命周期等问题

### 独立调用自举
如果用户直接调用 `sumeru-topic`，先执行轻量自举：
- 定位项目根目录；若不存在项目结构，可创建最小 `.sumeru/project.json`、`docs/requirements.md`、`ideas/`。
- 若已有 `.sumeru/project.json` 或 `docs/requirements.md`，复用其中的题材、平台、受众、篇幅，不重复询问。
- 选题完成后更新 `.sumeru/project.json`、`docs/requirements.md`、`ideas/*.md`、`.sumeru/decisions.md`。

### 按模式输出
- `short/light`：生成 1-3 个高概念创意，重点打磨核心反转、人物关系和结尾余味；可只更新 `outline.md` 和 `.sumeru/cache/story-brief.md`，不强制创建完整 `ideas/`。
- `medium/standard`：生成 3 个选题方案，更新 `docs/requirements.md`、`docs/creative-strategy.md` 或 `docs/outline.md`，创意库存可合并写入单文件。
- `long/full`：生成 3-5 个完整选题方案，写入 `ideas/concept-pitches.md`、`ideas/trope-breaker.md`、`ideas/cool-points.md`、`ideas/twists.md`，并保留完整评分表。

### 分析边界
- 市场判断基于模型知识和网文类型经验，不等同于实时榜单数据。
- 如果用户提供平台、榜单截图、书单或数据，应优先基于用户资料分析。
- 没有实时数据时，必须在报告中标注“非实时数据推断”，避免把推测写成确定事实。
- 选题应强调原创差异化，不直接套用知名作品的人物、组织、世界观和标志性桥段。

### 项目化输出要求
- 更新或创建 `docs/requirements.md`，记录目标平台、受众、篇幅、核心爽点、禁忌内容、推荐选题和待确认问题。
- 更新 `.sumeru/project.json` 中的 `genre`、`targetPlatform`、`audience`、`plannedWords`、`style`、`tone` 等已明确字段。
- 将选题决策记录到 `.sumeru/decisions.md`，说明为什么推荐该方案。
- 将待验证市场假设写入 `.sumeru/backlog.md`，例如需要用户补充平台榜单、竞品书单或目标读者偏好。
- 更新 `ideas/concept-pitches.md`、`ideas/trope-breaker.md`、`ideas/cool-points.md`、`ideas/twists.md`，保留可复用创意。

### 创意引擎输出要求
每次选题策划必须包含以下内容：

1. **高概念 Pitch**：至少 3 个一句话 pitch，每个都包含核心反差、爽点来源、代价/限制、传播句。
2. **类型混血**：至少 3 种类型嫁接方案，例如“修仙 + 职场 KPI”“都市商战 + 宗门经营”。
3. **金手指变异**：对常见金手指做至少 5 个变体，避免只给“签到/系统/重生”直给版本。
4. **反套路替代**：列出最容易落入的套路，并给出替代写法。
5. **读者记忆点**：每个候选选题至少给 2 个可传播名场面或安利句。
6. **创意评分表**：按新鲜度、爽感、合理性、可持续性、传播性、类型契合度评分。

推荐选题时，不只推荐综合分最高的方案，也说明“最稳妥方案”和“最有爆点方案”的取舍。

### 数据持久化
**用户可见输出（当前工作目录）**：
- `选题策划报告.md`：完整的选题策划报告（直接可读的Markdown格式）
- `docs/requirements.md`：同步后的创作需求文档（如项目结构已初始化）

**中间数据（仅系统内部使用，存于`.sumeru/topic/`目录）**：
- `report.md`：完整报告的备份
- `options.json`：所有多选题方案的结构化数据（JSON格式，供后续 skill 复用）
- `summary.json`：核心参数摘要，包含评分、推荐结论等

#### 与其他 Skill 配合
此 skill 生成的 `options.json` 可以被 `sumeru-outline` skill 自动读取：
- `sumeru-outline` 可以复用选题数据（通过自然语言指定"复用已有选题数据"）
- 大纲设计阶段会自动继承选题中的核心设定、金手指设计等内容
