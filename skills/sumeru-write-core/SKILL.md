## 网文章节撰写核心规则

> ⚠️ **这是通用写作规则**：`sumeru-write` 只使用这一种写作模式，不再区分 `light`/`medium`/`full`。

> 📌 **输出级别**：遵循 `sumeru-rules` 的输出级别规范。默认 `quiet`。

---

### 一、任务卡执行规则

**核心原则：工程保障底线（不犯错），创意突破上限（出彩）。**

#### 必须完成的事项

- 正文必须完成任务卡中的 `purpose`
- 正文必须落实 `creativeGoal`、`freshnessHook`、`emotionalBeat`、`readerMemoryPoint`
- 遇到 `tropeToAvoid` 时必须避开直给套路
- 若存在 `surpriseTwist`，必须提前埋下公平线索
- 正文必须满足全部 `acceptanceCriteria`

#### 创意自由度控制

| 级别 | 说明 | 适用场景 |
|------|------|----------|
| `low` | 严格按任务卡，禁止偏离 protectedElements | 高潮章、关键剧情节点 |
| `medium` | 可以添加毛边，但 purpose 不可偏离 | 过渡章、日常章、人物互动章 |
| `high` | 鼓励意外创意，只要不违背 protectedElements | 人物塑造章、情感章、伏笔回收章 |

创意自由度不是写作模式，只是任务卡字段。父Agent不得因为 `creativeFreedom` 切换到另一套写作规则。

**优先级规则：**
```
protectedElements（底线） → 不可违背
    ↓
purpose（必须完成） → 可以改变"如何完成"的方式
    ↓
allowedDeviations（鼓励添加） → 不强制，但鼓励
```

#### protectedElements 执行保障

**核心原则：子Agent不申请例外，由父Agent事后校验。**

1. 父Agent在 context pack 中明确列出 `protectedElements`（不可违背的底线）
2. 子Agent严格按 protectedElements 写作，不做任何例外申请
3. 子Agent输出后，父Agent对比 `state_diff` 与 `protectedElements`，检测是否违反
4. 发现违反时，父Agent暂停并询问用户（用户确认是否接受）

**父Agent校验逻辑：**
```
for each protectedElement in context_pack.protectedElements:
    if state_diff 中存在与 protectedElement 矛盾的变化:
        标记为 conflict，暂停写入，等待用户确认
```

### 二、创意落地五问（生成章节前自检）

1. **本章是否有读者能记住的一幕、一个选择或一句话？**
   - 如果没有 → 需要增加 readerMemoryPoint

2. **本章爽点是否和前 3 章重复？**
   - 如果重复 → 切换情绪类型或解决方式

3. **主角是否通过选择推动局势，而不是被剧情推着走？**
   - 如果不是 → 增加主角主动选择的情节

4. **反派或阻力是否足够聪明，是否让胜利付出代价？**
   - 如果不是 → 增加反派的反击或代价

5. **结尾钩子是否既承接本章输出，又诱导下一章点击？**
   - 如果不是 → 增加悬念或期待

### 三、剧情统一门禁

章节写作必须先保剧情统一，再追求文笔和爽点。任何出彩表达都不能覆盖既定剧情事实。

#### 写前必须确认

- 上一章实际结尾是否进入 context pack。
- 当前时间线、地点、人物位置是否明确。
- 关键人物的伤势、战力、关系、情绪状态是否明确。
- 关键道具、能力限制、伏笔状态是否明确。
- 本章禁止改写的事实是否列入 `protectedElements`。

#### 写中禁止事项

- 不得让同一人物无解释跨地点出现。
- 不得让已毁、已消耗、已转移的道具再次无因出现。
- 不得让伤势、战力、关系状态无因回退。
- 不得把已回收伏笔重新当作未解悬念使用。
- 不得为了爽点改写前文已经发生的事实。

#### 写后必须输出

`SUMERU_STATUS` 必须准确记录本章造成的状态变化；如果没有变化，也要输出空对象。

```markdown
<!-- SUMERU_STATUS: chapter=003, status=drafted, state_diff={}, char_update={}, plot_update={}, batch=001, timestamp=2026-05-18T10:30:00Z -->
```

父Agent只有在状态标记可解析、剧情统一校验通过后，才允许写入正式章节文件。

### 四、毛边核心原则

**记住三句话：**

1. **"少即是多"** — 每章 1-2 个毛边即可，不要堆砌
2. **"自然融入"** — 毛边要像长出来的，不是贴上去的
3. **"服务人物"** — 毛边是为了让人物更真实，不是为了炫技

**如果不确定要不要加毛边：**
- 加 → 读者会觉得"这人物是活的"
- 不加 → 读者会觉得"这人物在演戏"

**宁可加，不要不加。**

---

### 五、毛边场景触发机制

**用场景触发条件替代频率规则**（AI 容易判断是/否）：

| 毛边类型 | 触发场景条件 | 禁止条件 |
|----------|-------------|----------|
| **摸鼻子** | 社交压力 + 内心紧张 | 本章已使用过 → 不重复 |
| **转笔** | 独自思考 + 有他人在场但未对话 | 本章已使用过 → 不重复 |
| **胜利后的空虚** | 期待 3 章以上 + 付出重大代价 + 独自一人 | 小胜利/群体庆祝 → 不触发 |
| **对话停顿** | 情绪波动强烈时（紧张/愤怒/悲伤） | 日常对话 → 少用 |
| **手心出汗** | 重大决策前/首次公开场合 | 日常场景 → 不触发 |
| **腿软** | 战斗后/极度恐惧后 | 轻微冲突 → 不触发 |

**执行规则：**
1. 判断当前场景是否符合触发条件
2. 如果符合 → 可以添加该毛边
3. 如果本章已使用过同类毛边 → 不重复（避免套路化）
4. 如果不符合触发条件 → 不添加（避免滥用）

**习惯一致性与套路化的平衡：**
- 同一角色同一习惯：同一章内不重复，跨章可重复（建议间隔 ≥3 章）
- 每个角色定义 2-3 个习惯，不同场景随机选择不同习惯
- 角色经历重大事件后，可引入新习惯替代旧习惯（需在 char_update 中注明）
- 示例：主角前期紧张时摸鼻子(001-050)，经历生死战后改为深呼吸(051+)

---

### 六、避免的毛边类型

| 类型 | 示例 | 问题 |
|------|------|------|
| **偏离主线** | 添加与本章 purpose 无关的情节 | 跑偏，浪费篇幅 |
| **OOC 行为** | 内向角色突然社牛、谨慎角色突然冲动 | 破坏人物一致性 |
| **过度修饰** | 每句话都加形容词、每段都加心理描写 | 阅读疲劳 |
| **无意义口误** | 角色说错名字、说错地点 | 让读者困惑 |
| **情绪混乱** | 同一场景内情绪反复无常 | 读者看不懂人物 |
| **套路化毛边** | 每次紧张都摸鼻子，每次思考都皱眉 | 变成新套路 |

### 七、自检清单（写作完成后检查）

```markdown
## 人性化自检

### 人物
- [ ] 有没有添加人物小习惯（紧张/思考/情绪波动时）
- [ ] 人物行为是否符合性格（没有 OOC）
- [ ] 人物有没有意外但合理的选择

### 对话
- [ ] 对话有没有停顿、口误、打断
- [ ] 对话是不是太"完美"（每句都清晰完整）
- [ ] 对话有没有潜台词（言外之意）

### 情绪
- [ ] 情绪是不是单一（如只有狂喜）
- [ ] 有没有情绪层次（如"又开心又空虚"）
- [ ] 是不是用身体反应展现情绪（不是直接说）

### 场景
- [ ] 有没有与主线无关但增加真实感的细节
- [ ] 细节是不是堆砌（超过 2 个就要删减）
- [ ] 细节有没有功能（暗示人物状态/推动情绪）

### 整体
- [ ] 毛边有没有偏离主线 purpose
- [ ] 毛边是不是套路化（如每次紧张都摸鼻子）
- [ ] 读者会不会觉得"这人物是活的"

### 剧情统一
- [ ] 本章是否承接上一章实际结尾
- [ ] 人物位置、伤势、战力、关系是否与 continuity 一致
- [ ] 道具归属、消耗、损坏状态是否一致
- [ ] 伏笔是否只推进，不无因重置
- [ ] `state_diff` 是否完整记录本章变化
```
